Configuraciones en R

Una configuración: matriz p × k

Claude (2008, secc. 2.1.2): p filas (puntos) y k columnas (dimensiones). El orden de los puntos debe ser el mismo en todas las configuraciones.

Ejemplo del curso de 2011: un otolito de 50 pseudolandmarks guardado en CSV.

Formatos de archivo

Tres maneras de guardar contornos

1. Apilado sin identificador (datos/mcolaz1.txt): dos columnas x, y; cada otolito ocupa 50 filas seguidas. Compacto, pero frágil: si falta una fila, todos los otolitos siguientes quedan desplazados.

2. Largo (tidy): una fila por punto, con identificador.

id zona punto x y
Ch01 Ch 1 -370.1 447.4
Ch01 Ch 2 -414.1 388.4

3. Ancho: una fila por otolito, columnas x1…x50, y1…y50.

Recomendación: contornos en formato largo + una tabla de otolitos (id, zona, talla, sexo, edad, lado, archivo de imagen) relacionadas por id.

Leer los archivos apilados de tres zonas

zonas <- data.frame(zona   = c("Ch", "Ay", "Ma"),
                    nombre = c("Chiloé", "Aysén", "Magallanes"),
                    archivo = sprintf("datos/mcolaz%d.txt", 1:3))
np <- 50
leer_apilado <- function(archivo, zona) {
  d <- read.table(archivo, col.names = c("x", "y"))
  n <- nrow(d) / np
  stopifnot(n == round(n))                        # cada otolito = 50 filas
  data.frame(id    = sprintf("%s%02d", zona, rep(seq_len(n), each = np)),
             zona  = zona,
             punto = rep(seq_len(np), n),
             d)
}
largo <- do.call(rbind, Map(leer_apilado, zonas$archivo, zonas$zona))
rownames(largo) <- NULL

Escribir CSV

Validar los datos

Controles mínimos

validar_contornos <- function(d, np = 50) {
  pts <- table(d$id)
  c(otolitos          = length(pts),
    con_np_puntos     = sum(pts == np),
    NA_en_xy          = sum(is.na(d$x) | is.na(d$y)),
    puntos_duplicados = sum(duplicated(d[, c("id", "punto")])),
    orden_correcto    = all(unlist(tapply(d$punto, d$id, function(p) all(p == seq_len(np))))))
}
validar_contornos(cx)
#>          otolitos     con_np_puntos          NA_en_xy puntos_duplicados 
#>                67                67                 0                 0 
#>    orden_correcto 
#>                 1
all(unique(cx$id) %in% ot$id)     # ¿todos los contornos tienen metadatos?
#> [1] TRUE

Convertir entre formatos

Largo → arreglo p × k × n

Es el formato que usarán las funciones de Fourier (módulo 5).

largo_a_array <- function(d, np = 50) {
  ids <- unique(d$id)
  A <- array(NA_real_, dim = c(np, 2, length(ids)), dimnames = list(NULL, c("x", "y"), ids))
  for (i in ids) {
    di <- d[d$id == i, ]
    A[, , i] <- as.matrix(di[order(di$punto), c("x", "y")])
  }
  A
}
A <- largo_a_array(cx)

Guardar objetos de R y otros formatos

Claude (2008, secc. 2.4):

  • saveRDS(A, "datos/arreglo_3zonas.rds") / readRDS(): un objeto, formato binario de R (conserva dimensiones y nombres).
  • save(A, cx, file = "datos.RData") / load(): varios objetos con su nombre.
  • NTS y TPS (programas de Rohlf: tpsDig, tpsRelw): formatos de texto muy usados en morfometría geométrica; se leen con scan() y un poco de manipulación de texto (Claude 2008, pp. 56–58).
saveRDS(A, "datos/arreglo_3zonas.rds")

Buenas prácticas

  • Nombres de archivo sistemáticos (Zona1_oto001.pgm): permiten procesar lotes con bucles (Claude 2008, p. 28).
  • Una fila por observación, una columna por variable, una tabla por tipo de unidad.
  • Datos crudos de solo lectura; todo cambio se hace con código.
  • Codificación UTF-8; evitar tildes y espacios en nombres de columnas.
  • Documentar unidades (píxeles o mm), escala y umbral usados.
